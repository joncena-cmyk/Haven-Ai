## Summary Answer

HAVEN is a 6-stage capstone project (CINS, Group 3). It is a **two-service system**: a **Laravel 12 web app** and a **FastAPI ML microservice**. The full user journey is:

```
Register/Login  →  Add Vehicle (NHTSA VIN lookup)
→  Create Diagnostic Session (4-step wizard: vehicle select → live mic record → ESP32 CSV upload → review)
→  Submit  →  Run ML Analysis  →  View Results  →  Print Report
```

All data flows through the **database** (no session-to-session passing of form state) except for the audio blob, which is injected into a hidden file input by JavaScript `DataTransfer` before form submit. The ML analysis call is **synchronous** (no queue) and falls back to a PHP rule-based mock classifier if FastAPI is offline.

**Stages 1–6 are fully implemented. Stages 7–8 (Learning Modules) are placeholder only.**

## 2. Diagnostic Wizard — Complete Flow

The diagnostic creation wizard lives in `resources/views/diagnostics/create.blade.php`. It is a **single HTML form** (`POST /diagnostics`) broken into 4 visible steps by JavaScript — no AJAX, no intermediate requests. All data is submitted in one `multipart/form-data` POST.

### Step 1 — Select Vehicle

- Renders a `<select>` populated from `Auth::user()->vehicles()` ordered by make.
- Optional "Session Notes" textarea.
- If the user has no vehicles, the wizard is replaced with an empty state prompting vehicle registration.
- Pre-selects `vehicle_id` if passed as query param (used from the "New Session" button on `vehicles/show.blade.php`).
- Navigation: JS `goStep(2)` → hides `#step-1`, shows `#step-2`.

### Step 2 — Engine Audio

Two sub-panels toggled by tab buttons:

**"Record Live" panel:**
- Calls `navigator.mediaDevices.getUserMedia({audio:true})`.
- Creates a Web Audio API context + `AnalyserNode` for real-time waveform drawn to a `<canvas id="waveform">` using `requestAnimationFrame`.
- Uses `MediaRecorder` with 100ms chunks, produces a `Blob` of type `audio/webm`.
- On stop: creates a `File` from the blob named `engine-recording.webm`, injects it into `<input id="audio_blob" name="audio_blob" type="file">` via `DataTransfer.items.add()`.
- Duration (seconds) written to `<input type="hidden" id="audio_duration" name="audio_duration">`.
- Playback: `<audio>` element with `createObjectURL` as `src`.

**"Upload File" panel:**
- Plain `<input id="audio_file" name="audio_file" type="file">` accepting `.wav,.mp3,.webm,.ogg,.m4a`.

### Step 3 — Vibration Data

- `<input id="vibration_file" name="vibration_file" type="file" accept=".csv,.json,.txt">`.
- `onchange` handler reads the file in-browser via `FileReader`, parses CSV/JSON rows, computes **sample count / peak G / RMS G** client-side, and shows a preview panel + first 6 rows.
- Expected CSV format: `timestamp,x,y,z` (4-column) or `timestamp,magnitude` (2-column). JSON: array of objects with same keys.
- ESP32 sample rate: 50–200 Hz (documented in UI hint).

### Step 4 — Review & Submit

- `buildReview()` JS function assembles a summary from current form state:
  - Vehicle name from `<select>` text.
  - Audio: "Recorded (duration/size)" if blob exists, else filename if file selected, else "Not provided".
  - Vibration: filename + sample count preview, or "Not provided".
  - Notes (if any).
- Shows a warning flash if either data source is missing ("will be saved as draft").
- Shows a success flash if both present ("will be submitted for analysis").
- Submit button POSTs the form.

### POST /diagnostics — `DiagnosticController::store()`

**Validation:**
```php
'vehicle_id'     => required|integer|exists:vehicles,id
'audio_blob'     => nullable|file|mimes:webm,ogg,wav,mp3,mp4|max:51200 (50 MB)
'audio_file'     => nullable|file|mimes:webm,ogg,wav,mp3,mp4,m4a|max:51200
'vibration_file' => nullable|file|mimes:csv,json,txt|max:5120 (5 MB)
'notes'          => nullable|string|max:1000
```

**Logic:**
1. Verifies `vehicle.user_id === Auth::id()` — 404 if not.
2. Prefers `audio_blob` over `audio_file` (blob takes priority since it comes from live recording).
3. Audio stored at `storage/app/public/diagnostics/{vehicle_id}/audio/{filename}`.
4. `audio_duration_sec` set from the hidden form field (client-supplied — no server-side verification).
5. Vibration stored at `storage/app/public/diagnostics/{vehicle_id}/vibration/{filename}`.
6. `parseVibrationSummary()` is called synchronously on the uploaded file to compute `vibration_sample_count`, `vibration_peak_g`, `vibration_rms_g` — mirrors the client-side preview.
7. `status` is set to `'submitted'` if both audio AND vibration paths are present; `'draft'` otherwise.
8. `Diagnostic::create($data)` writes the row.
9. Redirects to `diagnostics.show` with a flash message.

**Data state after store:** The `Diagnostic` row exists in the DB. Files are on disk. `ml_condition`, `ml_confidence`, `ml_result_raw`, `ml_processed_at` are all null. Status is `draft` or `submitted`.

### GET /diagnostics/{diagnostic} — Show Page

- Loads the diagnostic with its vehicle.
- Renders the ML result panel (if `status === 'completed'` and `ml_condition` is set).
- Shows inline audio player (`<audio controls>`).
- Shows vibration stats (peak/RMS/crest factor) and download link.
- "Run Analysis" button POSTs to `diagnostics.analyze` if status is `draft` or `submitted`.
- "Re-analyze" available when `status === 'completed'`.

### POST /diagnostics/{diagnostic}/analyze — `DiagnosticController::analyze()`

1. `authorizeOwner()` — 403 if not owner.
2. Returns error if neither audio nor vibration is present.
3. Updates status to `'processing'`.
4. Calls `$ml->analyze($diagnostic)` (synchronous HTTP call to FastAPI, or PHP mock fallback).
5. On success: writes `ml_condition`, `ml_confidence`, `ml_result_raw` (full JSON), `ml_processed_at = now()`, status = `'completed'`.
6. On exception: sets status = `'failed'`, logs the error.
7. Redirects back to show page with flash message including condition + confidence + mock note if applicable.

## 4. ML Pipeline — End-to-End

### Laravel → FastAPI (`MlBackendService.php`)

**Trigger:** `POST /diagnostics/{diagnostic}/analyze` → `DiagnosticController::analyze()` → `MlBackendService::analyze(Diagnostic $diagnostic)`.

**Step 1 — Liveness check:**
```
GET http://localhost:8001/health   (3s timeout)
```
If this fails, the service short-circuits to the PHP mock classifier.

**Step 2 — File attachment:**
Using Laravel's `Http::asMultipart()`:
- If `$diagnostic->audio_path` is set and the file exists on disk: attaches as `audio_file` with the original filename.
- If `$diagnostic->vibration_path` is set and the file exists: attaches as `vibration_file`.
- Always sends form fields: `diagnostic_id` (int), `vehicle_id` (int).

**Step 3 — POST to FastAPI:**
```
POST http://localhost:8001/analyze
Content-Type: multipart/form-data

Fields: audio_file (File), vibration_file (File), diagnostic_id (int), vehicle_id (int)
```
Timeout: 30 seconds (configurable via `ML_BACKEND_TIMEOUT` env).

**Step 4 — Response parsing:**
On HTTP 2xx, returns `$response->json()` directly.
On non-2xx or connection error, calls `mockAnalysis($diagnostic, reason)` instead of throwing.

### FastAPI — `POST /analyze` (`main.py`)

1. Validates: at least one of `audio_file` or `vibration_file` must be present (HTTP 422 otherwise).
2. Audio: writes upload to a temp file, calls `extract_audio_features(tmp_path)` from `features.py`, deletes temp file.
3. Vibration: writes upload to a temp file, calls `extract_vibration_features(tmp_path, ext)`, deletes temp file.
4. Merges audio + vibration features into one dict.
5. Calls `classifier.predict(all_features)`.
6. Returns JSON:

```json
{
  "diagnostic_id": 42,
  "vehicle_id": 7,
  "condition": "knocking",
  "confidence": 0.812,
  "confidence_pct": "81.2%",
  "top_classes": [
    {"condition": "knocking",  "confidence": 0.812},
    {"condition": "normal",    "confidence": 0.134},
    {"condition": "misfiring", "confidence": 0.054}
  ],
  "features_used": ["peak_g", "rms_g", "crest_factor", "rms_mean", "zcr_mean", ...],
  "audio_features": { "rms_mean": ..., "mfcc_1_mean": ..., ... },
  "vibration_features": { "peak_g": ..., "rms_g": ..., "crest_factor": ..., "sample_count": ... },
  "mode": "rule_based",
  "warnings": [],
  "processed_at": "2026-10-20T01:00:00Z"
}
```

### Feature Extraction (`features.py`)

**Audio features** (requires `librosa`):
| Feature | Description |
|---|---|
| `rms_mean`, `rms_std` | Root mean square energy |
| `zcr_mean`, `zcr_std` | Zero-crossing rate |
| `spectral_centroid_mean/std` | Brightness of sound |
| `spectral_rolloff_mean` | Frequency below which 85% energy falls |
| `spectral_bandwidth_mean` | Spectral spread |
| `mfcc_1..13_mean`, `mfcc_1..13_std` | 26 MFCC features |
| `duration_sec`, `sample_rate` | Metadata |

Fallback if librosa missing: returns file size + estimated duration only.

**Vibration features** (pure numpy):
| Feature | Description |
|---|---|
| `peak_g` | Maximum magnitude across all samples |
| `rms_g` | Root mean square of magnitudes |
| `mean_g` | Mean magnitude |
| `std_g` | Standard deviation |
| `crest_factor` | `peak_g / rms_g` — impulsiveness ratio |
| `sample_count` | Number of data rows |

### Classifier (`classifier.py`)

**Model loading:** On startup, attempts `pickle.load("model.pkl")`. Expected format:
```python
{"model": sklearn_pipeline, "meta": {"feature_order": [...], "trained_on": "...", "accuracy": 0.94}}
```
No `model.pkl` exists yet — the backend always runs in rule-based mode.

**Rule-based fallback thresholds:**
| Condition | Triggers |
|---|---|
| `knocking` | `peak_g > 3.5` OR `crest_factor > 4.5` |
| `misfiring` | `zcr_mean > 0.18` OR (`crest > 3.0` AND `peak_g < 3.5`) |
| `overheating` | `spectral_centroid > 5000` AND `rms_mean > 0.05` |
| `idling_rough` | `1.5 < peak_g ≤ 3.5` AND `zcr < 0.12` |
| `normal` | Default (base score 0.25; winner when no other rule triggers strongly) |

Scores are normalized to probabilities; top 3 returned.

### PHP Mock Classifier (`MlBackendService::mockAnalysis()`)

Used when FastAPI is offline. Uses only the vibration stats already stored on the `Diagnostic` row:

| Condition | PHP Rule |
|---|---|
| `knocking` | `peak_g > 3.5` OR `crest > 4.5` |
| `misfiring` | `crest > 3.0` AND `peak_g < 3.5` |
| `idling_rough` | `rms_g > 0.4` AND `peak_g < 2.0` |
| `normal` | Default (base 0.20) |
| `overheating` | Not scored — audio features not available in mock |

Response includes `mode: "mock_{reason}"` and a warnings array. The show view displays "Simulated result (ML server offline)" when `mode` contains "mock".

### Results Storage

After a successful (or mock) analysis, `DiagnosticController` writes:
```php
$diagnostic->update([
    'status'          => 'completed',
    'ml_condition'    => $result['condition'],     // string e.g. "knocking"
    'ml_confidence'   => $result['confidence'],    // float 0.0–1.0

```

### Results Display

`diagnostics/show.blade.php` renders:
- Condition name (large, colored by severity: green = normal, amber = misfiring/idling_rough, red = knocking/overheating/unknown)

## 5. NhtsaVehicleService — VIN Lookup End to End

**Source:** `app/Services/NhtsaVehicleService.php`  
**API:** NHTSA vPIC public API (`https://vpic.nhtsa.dot.gov/api/vehicles`) — no API key.

### Makes endpoint (`GET /vehicles/catalog/makes`)
- Calls `GetMakesForVehicleType/{type}` for types: `car`, `truck`, `mpv`.
- Deduplicates by uppercased name.
- Title-cases results (BMW, GMC, Kia are corrected as special cases).
- **Cached 24 hours** under key `nhtsa.makes.v1`.
- Returns `{"makes": ["Acura", "BMW", "Ford", ...]}`.

### Models endpoint (`GET /vehicles/catalog/models?make=Toyota&year=2020`)
- Calls `GetModelsForMakeYear/make/{make}/modelyear/{year}` (if year given) or `GetModelsForMake/{make}`.
- **Cached 12 hours** per make+year combo: key `nhtsa.models.v1.{md5(make|year)}`.
- Returns `{"models": ["Camry", "Corolla", ...]}`.

### VIN decode endpoint (`GET /vehicles/catalog/vin?vin=1HGCM82633A004352`)
- Validates: 17 chars, strips invalid characters (I, O, Q not allowed).
- Calls `DecodeVinValues/{vin}`.
- Extracts: `Make`, `Model`, `ModelYear`, `EngineModel`/`DisplacementL`/`EngineCylinders`/`EngineConfiguration`, `TransmissionStyle`/`TransmissionDescriptor`.
- Maps transmission style strings to app's enum (`Manual`, `Automatic`, `CVT`, `Other`).
- Composes engine string: prefers `EngineModel`, else builds from displacement + cylinders + config (e.g. "1.3L 4-cyl").
- Returns `{vin, make, model, year, engine_type, transmission}`.
- Throws `InvalidArgumentException` for a bad VIN (passed to JS as `data.error`).
- **Not cached** (VIN decodes are per-vehicle, low frequency).

### Client-side flow (`catalog-fields.blade.php`)
1. Page load: calls `/vehicles/catalog/makes` via `fetch()`, populates `<select id="make_select">`.
2. Make change: fetches models for selected make + current year.
3. Year change: re-fetches models.
4. "Other (type manually)": shows free-text `<input>` beneath the dropdown; hidden input carries the value to form submit.
5. VIN decode button: fetches `/vehicles/catalog/vin?vin=...`, fills `year`, `engine_type`, `transmission` fields, then triggers `loadMakes` + `loadModels` with the decoded values.

## 7. Middleware, Policies, and Gates

### Active Middleware

| Middleware | Where Applied | What it does |
|---|---|---|
| `auth` | All protected routes | Redirects unauthenticated users to `/login` |
| `verified` | All protected routes | Redirects unverified users to `/verify-email` |
| `guest` | Auth routes (login, register) | Redirects authenticated users away |
| `signed` | `verify-email/{id}/{hash}` | Validates signed URL |
| `throttle:6,1` | Verify email + send notification | 6 requests per minute |

**⚠ Mismatch:** The `verified` middleware is applied everywhere, but `User` does not implement `MustVerifyEmail` (the interface is commented out in `User.php`). This means newly registered users are never sent a verification email and cannot use the app until `email_verified_at` is manually set or the middleware is removed.

### Authorization

No Laravel Gates or Policies exist. Authorization is done manually in every controller:
```php
// VehicleController and DiagnosticController
private function authorizeOwner(Vehicle|Diagnostic $record): void {
    abort_if($record->user_id !== Auth::id(), 403);
```

## 10. Findings and Recommendations

### Critical Bugs

**1. Email verification middleware mismatch**  
`User` does not implement `MustVerifyEmail` (interface commented out), but all protected routes use `->middleware(['auth', 'verified'])`. New users never receive a verification email, so `email_verified_at` stays null, and the `verified` middleware redirects them to the verify-email prompt indefinitely. **Fix:** Either uncomment `MustVerifyEmail` in `User.php` or remove `'verified'` from the route middleware group.

**2. Synchronous ML analysis in HTTP request**  
`DiagnosticController::analyze()` calls `MlBackendService::analyze()` synchronously. For 50 MB audio files plus FastAPI processing time, this will hit PHP's default 30-second execution timeout. The queue infrastructure (jobs table) is already set up. **Fix:** Extract analysis into a `AnalyzeDiagnosticJob` queued job.

### Significant Gaps

**3. No diagnostic edit route**  
A `draft` diagnostic (e.g., only audio captured) cannot have files added to it. Users must delete and recreate. **Fix:** Add `diagnostics.edit` / `diagnostics.update` routes and a simple form to attach missing files.

**4. No trained ML model**  
The entire point of the project. `model.pkl` is absent. Both the FastAPI rule-based classifier and PHP mock produce heuristic guesses, not data-trained predictions. The feature extraction pipeline is production-ready. **Next step:** Collect labeled engine recordings, train a scikit-learn pipeline, and drop `model.pkl` into `ml_backend/`.

**5. `audio_duration_sec` trusted from client**  
The duration is set by a JavaScript hidden input and submitted as a form field. A malicious or misconfigured client could send any value. **Fix:** Either measure duration server-side using FFmpeg/getID3 or at minimum add a max/min validation rule.

### Minor Issues

| Issue | Fix |
|---|---|
| `ML_BACKEND_URL` missing from `.env.example` | Add `ML_BACKEND_URL=http://localhost:8001` |
| CORS hard-coded to `localhost:8000` in FastAPI | Replace with env var |
| NHTSA `titleCase()` only corrects 3 brands | Expand the correction map or apply a smarter heuristic |
| No test coverage for `DiagnosticController`, `MlBackendService`, `NhtsaVehicleService` | Write feature tests for store/analyze, unit tests for services |
| `vehicles/show.blade.php` "Start Diagnostic" button is disabled (Stage 4 note still in UI) | Enable the button and link to `diagnostics.create?vehicle_id={id}` — the route exists and works |
| No policies/gates — `abort_if` pattern in every controller | Introduce `VehiclePolicy` + `DiagnosticPolicy` via `php artisan make:policy` |
